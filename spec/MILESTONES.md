# MILESTONES — חידונצ'יק

מסמך זה מחלק את פיתוח האפליקציה לאבני דרך (Milestones). הוא מבוסס על `PRD.md`, `ARCHITECTURE.md` ו־`DESIGN.md`, ואינו מוסיף פיצ'רים שאינם מופיעים בהם.

**עקרון החלוקה:** כל Milestone, מלבד ההקמה, הוא Vertical Slice. כלומר, יכולת משתמש שלמה שעובדת מקצה לקצה: ממשק, API ו־AI. בסיום כל Milestone האפליקציה במצב עובד וניתנת לבדיקה.

**הערה על סביבות:** לפי `ARCHITECTURE.md` אין בפרויקט Database (ואין Supabase), ולכן אין Database Migrations. ההפרדה בין הסביבות נעשית ברמת משתני הסביבה ומפתחות ה־API:
- **Development:** פיתוח מקומי ו־Preview Deployments ב־Vercel, עם מפתח OpenAI לפיתוח.
- **Production:** האתר הציבורי ב־Vercel, עם מפתח Production שמוגדר רק ב־Vercel.

---

## Development Execution Rules — הנחיות ל־AI המבצע את הפיתוח

> **חובה לפעול לפי הכללים הבאים:**
> 1. יש לפתח את ה־Milestones **לפי הסדר** שהוגדר במסמך זה.
> 2. לאחר השלמת כל Milestone **יש לעצור את הפיתוח** ולהציג למשתמש:
>    - את התוצר שהושלם (מה עובד וכיצד לבדוק אותו).
>    - את תוצאות הבדיקות מול כל סעיף ב־Definition of Done (עבר / נכשל).
> 3. **אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש.**
> 4. פעולות שהמשתמש צריך לבצע בעצמו (יצירת חשבונות, הגדרת מפתחות API, הגדרות ב־Vercel או ב־GitHub) יוצגו לו **כהדרכה צעד אחר צעד**, בשפה פשוטה.
> 5. אין להוסיף פיצ'רים, מסכים או יכולות שאינם מוגדרים ב־`PRD.md`, ב־`ARCHITECTURE.md` או ב־`DESIGN.md`. כשיש שאלה פתוחה, יש לעצור ולשאול את המשתמש.
> 6. אין לשמור סודות (`OPENAI_API_KEY`, קובצי `.env.local`) ב־Git, ואין לחשוף אותם בקוד צד־לקוח.

## Milestone 1 — הקמת הפרויקט ומעטפת האפליקציה

**שם ומטרה:** להקים את הפרויקט ואת תשתית הפריסה, ולבנות את מעטפת האפליקציה עם השפה העיצובית. בסיום, אפשר לפתוח את האתר, לראות את מסך הבית ומסך אודות ולנווט ביניהם.

**מה יש לממש:**
- פרויקט Next.js (App Router) עם TypeScript, ו־`.gitignore` שמחריג את קובצי `.env*` (למעט קובץ דוגמה ללא ערכים).
- Git Repository ב־GitHub וחיבור ל־Vercel עם Deployment אוטומטי ו־Preview Deployments. המשתמש מבצע את השלב הזה בהדרכה צעד אחר צעד.
- הגדרות שורש: `lang="he"`, `dir="rtl"`, טעינת הגופנים Rubik ו־Heebo, ו־Fallback ל־Arial.
- Design tokens לפי `DESIGN.md`: צבעים, טיפוגרפיה, radius, צללים ו־Spacing.
- רכיבים משותפים לפי `DESIGN.md`:
  - כפתור Primary וכפתור Secondary.
  - Input.
  - Card.
  - Top bar עם כפתור חזרה.
  - Bottom tab bar עם הלשוניות `אודות`, `בית`, `שאלות`.
  - Chip.
  - סט אייקונים.
- **מסך הבית:**
  - שם האפליקציה וכותרת משנה.
  - איורי הנושאים.
  - כרטיס עם הכותרת `איזה נושא מעניין אותך?`, ושדה טקסט עם placeholder `לדוגמה: חיות, חלל, מדע ועוד...`.
  - כפתור `התחל` וכפתור `אודות`.
- **מסך אודות:** הטקסט, ה־chip `גרסה 1.0` וה־Bottom tab bar, כמוגדר ב־`DESIGN.md`.
- **מסלול מסך השאלות:** קיים ונגיש מהלשונית `שאלות` ומהכפתור `התחל`, עם Top bar בלבד. התוכן יתווסף ב־Milestone 2.

**תוצר מצופה:** אתר שעלה ל־Preview Deployment ב־Vercel. האתר מציג את מסך הבית ומסך אודות בעיצוב הסופי, ואפשר לנווט בין שלושת המסלולים.

**Definition of Done:**
- [ ] `npm run build` עובר ללא שגיאות.
- [ ] Push ל־GitHub יוצר Preview Deployment תקין ב־Vercel.
- [ ] מסך הבית ומסך אודות תואמים את `mockups.png` ואת `DESIGN.md`: צבעים, גופנים, RTL וטקסטים.
- [ ] ה־Bottom tab bar מנווט בין `בית`, `אודות` ו־`שאלות`, והלשונית הפעילה מסומנת בהתאם.
- [ ] `אודות` (כפתור) ו־`התחל` מנווטים למסכים הנכונים.
- [ ] התצוגה תקינה ברוחב מסך של טלפון (360–430px), ללא גלילה אופקית, ואזורי הלחיצה בגודל 44px לפחות.
- [ ] אין קובצי `.env` עם ערכים ב־Repository.

## Milestone 2 — יצירת שאלה והצגתה (מקצה לקצה)

**שם ומטרה:** הילד מזין נושא, או משאיר את השדה ריק, לוחץ `התחל` ומקבל שאלת טריוויה אמיתית שנוצרה ב־GPT-5. אם משהו נכשל, מוצגת לו הודעת שגיאה ידידותית עם אפשרות לנסות שוב.

**מה יש לממש:**
- **אימות זמינות המודל:** המשתמש מקבל הדרכה צעד אחר צעד ליצירת מפתח OpenAI לפיתוח, ולהגדרתו ב־`.env.local` וב־Preview של Vercel. לאחר מכן בודקים שהמודל `gpt-5` זמין לחשבון. **אם המודל אינו זמין, יש לעצור ולבקש מהמשתמש החלטה על מודל חלופי. אין להחליף את המודל בשקט.**
- **משתני סביבה:** `OPENAI_API_KEY` ו־`OPENAI_MODEL`, בצד השרת בלבד, ללא קידומת `NEXT_PUBLIC_`.
- **`POST /api/trivia`** (Route Handler), לפי החוזה ב־`ARCHITECTURE.md`:
  - בדיקת קלט: מחרוזת והגבלת אורך.
  - נושא ריק מטופל כבקשה לשאלה כללית.
  - Trivia Service עם הנחיות קבועות למודל: עברית, גילאי 9–12, שאלה אחת, ארבע אפשרויות ותשובה נכונה אחת.
  - OpenAI Adapter עם ה־SDK הרשמי ו־Structured Outputs (JSON Schema), אם המודל תומך בכך.
  - בדיקת הפלט בשרת: בדיוק ארבע אפשרויות לא ריקות, ו־`correctOptionIndex` בטווח 0–3.
  - timeout לקריאה ל־OpenAI, ומגבלה על אורך הפלט.
  - תגובת `503` עם `QUESTION_UNAVAILABLE` בכל כשל, ללא חשיפת פרטים פנימיים.
- **API Client** בצד־לקוח.
- **מסך יצירת שאלה** (מצב טעינה): אייקון מוח, `מכין שאלה עבורך...`, `זה ייקח רק כמה שניות`, ו־Progress bar. כפתור `התחל` מושבת בזמן הבקשה, כדי למנוע לחיצה כפולה.
- **מסך שאלה:** Question card ועוד ארבע אפשרויות תשובה, במצב Default.
- **מסך שגיאה:**
  - `אופס!` והטקסט `אירעה תקלה בהכנת השאלה. אנא נסה שוב.`
  - כפתור `נסה שוב`, ששולח שוב את אותה בקשה.
  - כפתור `חזרה לבית`.

**תוצר מצופה:** מתוך מסך הבית אפשר לקבל שאלת טריוויה אמיתית בעברית לפי נושא, או שאלה כללית, ולראות אותה עם ארבע אפשרויות. תקלות מובילות למסך השגיאה.

**Definition of Done:**
- [ ] זמינות `gpt-5` אומתה, או שהתקבלה החלטה מתועדת של המשתמש על מודל אחר.
- [ ] נושא תקין (לדוגמה `חלל`) מחזיר שאלה בעברית עם ארבע אפשרויות, ומוצג במסך השאלה.
- [ ] שדה ריק מחזיר שאלה כללית.
- [ ] מצב הטעינה מוצג בזמן הבקשה, ואי אפשר לשלוח בקשה כפולה.
- [ ] כשל מדומה (רשת, timeout, פלט לא תקין) מוביל למסך השגיאה. `נסה שוב` ו־`חזרה לבית` עובדים.
- [ ] פלט חסר או לא תקין לעולם אינו מוצג כשאלה.
- [ ] מפתח ה־API אינו מופיע בקוד הלקוח, בתגובות ה־API או ב־Repository (נבדק בכלי הפיתוח של הדפדפן ובחיפוש בקוד).
- [ ] Unit Tests לולידציית הנושא, למיפוי לשאלה כללית ולבדיקת מבנה השאלה. API Tests לתגובות `200` ו־`503`. כל הבדיקות עוברות.
- [ ] המסכים תואמים את `DESIGN.md` ואת `mockups.png`.

## Milestone 3 — מענה, משוב וניקוד (לולאת המשחק המלאה)

**שם ומטרה:** הילד בוחר תשובה, מקבל משוב ורואה את הניקוד שלו. אחר כך הוא יכול להמשיך לשאלה הבאה באותו נושא, או לחזור ולהחליף נושא.

**מה יש לממש:**
- **Game State בזיכרון בלבד:** `currentTopic`, `currentQuestion`, `answered`, `feedback`, `score`. לא נשמר ב־Local Storage, ב־Cookies או בשרת.
- **בחירת תשובה:**
  - רק הבחירה הראשונה נחשבת.
  - אחרי הבחירה כל האפשרויות ננעלות (מצב Locked).
  - הניקוד מתעדכן פעם אחת לכל היותר לכל שאלה.
- **מסך תשובה נכונה:** כרטיס Mint, `כל הכבוד!`, `התשובה נכונה` וכפתור `שאלה הבאה`. הניקוד עולה בנקודה אחת. התווית `+1 נקודה` אופציונלית לפי `DESIGN.md`, ויש לשאול את המשתמש אם לכלול אותה.
- **מסך תשובה שגויה:** כרטיס Coral, `לא נכון`, `התשובה הנכונה היא:`, תיבה ובה התשובה הנכונה, וכפתור `שאלה הבאה`. הניקוד לא משתנה.
- **Score chip** (`ניקוד: N`) במסך השאלה ובמסכי המשוב.
- **`שאלה הבאה`:** בקשה חדשה באותו נושא, דרך מסך הטעינה.
- **החלפת נושא:** חזרה למסך הבית, ושם הזנת נושא חדש. הניקוד נשמר בזיכרון לאורך הסשן.

**תוצר מצופה:** לולאת משחק מלאה ועובדת: נושא, שאלה, תשובה, משוב, שאלה הבאה או נושא חדש. הניקוד מצטבר לאורך הסשן.

**Definition of Done:**
- [ ] תשובה נכונה מציגה את מסך ההצלחה ומעלה את הניקוד ב־1.
- [ ] תשובה שגויה מציגה את מסך הכישלון ואת התשובה הנכונה, והניקוד לא משתנה.
- [ ] לחיצות חוזרות או מהירות על אפשרויות אינן משנות את הבחירה ואינן מעלות את הניקוד יותר מפעם אחת.
- [ ] `שאלה הבאה` מביא שאלה חדשה באותו נושא.
- [ ] חזרה למסך הבית מאפשרת להזין נושא חדש, והניקוד נשמר.
- [ ] טעינה מחדש של הדף מאפסת את הניקוד, ושום דבר לא נשמר בדפדפן.
- [ ] UI Tests לבחירה אחת בלבד, להצגת משוב, לחשיפת התשובה הנכונה ולעדכון הניקוד. Unit Tests לחישוב הניקוד. כל הבדיקות עוברות.
- [ ] המסכים תואמים את `DESIGN.md` ואת `mockups.png`.

## Milestone 4 — בטיחות ילדים וסינון נושאים

**שם ומטרה:** לוודא שנושאים שאינם מתאימים לילדים נדחים בהודעה ידידותית, ושתוכן לא מתאים לא מוצג לעולם.

**מה יש לממש:**
- **סינון רב־שכבתי ב־Backend,** לפי `ARCHITECTURE.md`:
  - בדיקת קלט.
  - OpenAI Moderation API לבדיקת הנושא.
  - הנחיות מפורשות למודל, כולל התעלמות מהוראות שמופיעות בתוך הנושא.
  - בדיקת התוכן שנוצר לפני החזרתו.
- **נושא שנדחה:** תגובת `422` עם `TOPIC_NOT_ALLOWED`, בלי לבקש מהמודל ליצור שאלה.
- **הודעה למשתמש על נושא לא מתאים:**
  - הטקסט: `הנושא הזה לא מתאים לחידון. נסו לבחור נושא אחר.`
  - העיצוב: לפי השפה החזותית של מסך השגיאה (Tangerine).
  - `DESIGN.md` מגדיר את פריסת המצב הזה כנקודה פתוחה. **לפני המימוש יש להציג למשתמש הצעת פריסה ולקבל את אישורו.**
- **לוגים מצומצמים:** קוד שגיאה, משך הבקשה ומזהה בקשה, ללא שמירת נושאים או תוכן.

**תוצר מצופה:** נושאים לא מתאימים נחסמים בהודעה ידידותית, ונושאים תמימים ממשיכים לעבוד כרגיל.

**Definition of Done:**
- [ ] פריסת הודעת "נושא לא מתאים" אושרה על ידי המשתמש ומומשה.
- [ ] רשימת נושאים לבדיקה (תמימים, עמומים ולא מתאימים) נבדקה ידנית, והתוצאות מוצגות למשתמש.
- [ ] נושא לא מתאים מחזיר `422`, מציג את ההודעה הידידותית ואינו מציג שאלה.
- [ ] ניסיון להכניס הוראות בתוך הנושא (Prompt Injection) אינו משנה את כללי המערכת.
- [ ] תוכן שנכשל בבדיקה אינו מוצג למשתמש.
- [ ] Safety Tests ו־API Tests ל־`422` עוברים.
- [ ] הלוגים אינם מכילים נושאים או תוכן מלא.

## Milestone 5 — PWA ופריסה ל־Production

**שם ומטרה:** לאפשר התקנה של האפליקציה כ־PWA, להקשיח את נקודת ה־API לקראת פתיחה ציבורית, ולפרסם את האתר ב־Production.

**מה יש לממש:**
- **Web App Manifest:**
  - שם `חידונצ'יק` ושם מקוצר.
  - אייקונים בגדלים הנדרשים.
  - `start_url` ו־`display: "standalone"`.
- **Service Worker מינימלי:** שומר במטמון רק משאבים סטטיים ואת מעטפת האפליקציה. לא שומר שאלות, תשובות, ניקוד או תגובות API.
- **מצב Offline:** כשאין חיבור לאינטרנט, ניסיון ליצור שאלה מציג את הודעת השגיאה הידידותית.
- **Rate Limiting** לנקודת ה־API, באמצעות שירות הגנה מתאים של הפלטפורמה.
- **סביבת Production:** המשתמש מבצע בהדרכה צעד אחר צעד:
  - יצירת מפתח OpenAI נפרד ל־Production והגדרתו כמשתנה סודי ב־Vercel בלבד.
  - הגדרת `OPENAI_MODEL`.
  - הגדרת תקציב והתראות חיוב בחשבון OpenAI.
  - בדיקת התאמת תוכנית Vercel לשימוש המיועד (Hobby לשימוש אישי בלבד).
- **Production Deployment** מהענף הראשי.

**תוצר מצופה:** האתר זמין ב־Production בכתובת ציבורית, ניתן להתקנה כ־PWA, וכל הזרימות עובדות.

**Definition of Done:**
- [ ] משתני Production מוגדרים ב־Vercel בלבד, עם מפתח נפרד ממפתח הפיתוח.
- [ ] Production Deployment הצליח, והאתר וה־API עובדים בכתובת הציבורית.
- [ ] האפליקציה ניתנת להתקנה ונפתחת במצב standalone. נבדק בפועל ב־Chrome ב־Android וב־Safari ב־iOS.
- [ ] במצב Offline המעטפת נטענת, וניסיון ליצור שאלה מציג הודעת שגיאה ידידותית.
- [ ] ה־Service Worker אינו שומר במטמון שאלות, תשובות או ניקוד.
- [ ] Rate Limiting פעיל, ובקשות חריגות נחסמות.
- [ ] Manual QA מלא ב־Production:
  - נושא ריק.
  - נושא תקין.
  - נושא לא מתאים.
  - תשובה נכונה ותשובה שגויה.
  - לחיצה כפולה.
  - שגיאה וניסיון חוזר.
  - ניווט בין כל המסכים.
  - RTL ותצוגה במסכים קטנים.
- [ ] כל הבדיקות האוטומטיות עוברות.
